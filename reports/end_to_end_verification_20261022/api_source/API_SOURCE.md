## Findings that affect interpretation

1. **The UI default and API metadata use different meanings of primary.** `/` and `/api/config` advertise `direct_12month_research` as the primary research product. A district page without a `view` or `origin_month` query selects `experimental_12month_scenario`, which produces twelve assumption-based monthly points. `view=historical` or an `origin_month` query selects the direct historical graph, except that explicit `view=scenario` takes precedence. The current `api_spec.md` opening paragraph documents this distinction; the root/config metadata does not enumerate the scenario as the UI default. This is naming/metadata inconsistency, not evidence that six-month ML became twelve-month ML. Sources: `api/app.py:103`, `api/routes/scores.py:22`, `dashboard/src/components/experimentalScenarioContract.js:53`, `dashboard/src/components/DistrictForecastGraph.jsx:8`.

2. **A clean clone cannot reproduce the locally running app's numerical products.** The checked-in research descriptor points to six locally present but untracked frozen bundle files under `reports/candidates/twelve_month_horizon_finalization_20261020/artifact/`. National scenarios need ignored `data/processed/features_matrix.csv` and `feature_manifest.json`. Legacy APIs need an existing matching PostgreSQL database and ignored six-month/climate pointers, cards and models. This is explicitly acknowledged in `deploy/README.md`; Git source availability does not establish runtime artifact availability.

3. **The default Docker package omits the frozen research bundle.** `.dockerignore:13` excludes `reports`, `Dockerfile.api` copies the remaining build context, and Compose mounts only `/app/data` and `/app/models/checkpoints`, both read-only. It does not mount the direct research `reports` namespace. Even with valid mounted legacy data/checkpoints and a restored DB, direct catalog/forecast/graph and the special Adilabad scenario source cannot find their default frozen artifact in this image. Other districts' scenarios can use the data mount if its exact pinned hashes match. `/api/health` and Waitress startup readiness validate legacy DB/model/score publication, so passing them does not certify this research bundle. No Docker build or deployment was attempted. Sources: `.dockerignore`, `deploy/Dockerfile.api`, `deploy/compose.yaml:20`, `deploy/serve.py:25`, `models/experimental_scenario.py:84`.

4. **The observed 403 demo boundary is intentional local demonstration behavior.** `reports/candidates/twelve_month_graph_only_20261021/demo_server.py:32` adds a `before_request` guard to a normal factory app. It allows only GET/OPTIONS for `/`, `/api/config`, `/api/research/forecast`, and paths beginning `/api/research/forecast/` or `/api/research/graph/`. Every other route, including `/api/scores`, `/api/district`, `/api/history`, `/api/predict`, `/api/health`, `/api/simulate` and the subsequently added scenario route, returns HTTP 403 with `Legacy routes are excluded from this read-only demonstration.` The helper patches DB connections and XGB `.fit` to fail and binds `127.0.0.1:5051` when run directly (`:45`). Normal `api.app.create_app` registers these routes without this hook and has no authentication/authorization guard. CORS origin filtering is separate and does not explain this deliberate 403. A 403 from the original 5051 helper is not evidence that the normal API's DB, model or credentials failed.

## Method identity, cutoffs and causal limits

The direct bundle locks schema version 1, exact twelve features/order and schema hash, `m_bgl` target, rainfall/ET `mm/month`, temperature `degC`, twelve-month embargo, `historical_research_only`, Adilabad scope, protocol/configuration hashes, source generation, model settings and all manifest/card/model/snapshot/provenance byte hashes **before** deserialization. Paths are confined to the dedicated `reports/candidates/twelve_month_horizon_*` namespace. Research model/card hashes are in the receipt; the active six-month and monthly-climate artifacts have different identities and loader contracts. The same feature list alone does not make them interchangeable.

The fixed direct artifact's recorded training-target cutoff is 2021-12-31, latest training target 2021-12-01, latest training origin 2020-12-01; the first admitted app origin is 2023-01. Both selected origin and exact origin+12 target must be source-marked observed/non-imputed. The annual reference equals the observed origin (persistence = annual seasonal naive at M+12); it may survive when ML is unavailable, but it is not independent model evidence. `observed_target_m` is used only to classify/label retrospective research. `model.predict` receives only `row[FEATURES]`, never the target. Default origin 2026-05 targets 2027-05 and is unavailable ML by design because no exact observed target is archived; a historical origin such as 2024-01 can be inspected explicitly. These source/code-derived defaults are not a new inference run.

Direct input provenance requires known source/required months, source ≤ required ≤ origin, consistent integer age, at most three months groundwater carry or two months weather carry, correct calendar lags and recursively compatible derived dependencies. Unknown, missing, future or stale inputs block ML. Preprocessing separately uses bounded causal forward carry (GWL 3, climate 2); no backward interpolation supplies production observations. The legacy `sarima_fill` helper is unlimited forward fill but is not called by `run_pipeline`. No preprocessing was executed here.

Legacy evidence filtering admits the current month on its last calendar day, otherwise only earlier completed months. It requires at least 24 observed months plus 60% coverage of expected three-month monitoring rounds, then explicitly falls back to a real zone aggregate or returns insufficient evidence. Zone GWL uses observed rows, with bounded forward carry for features; fills never advance observed origin. The legacy card locks horizon 6, feature order/hash, units, model/card hashes, generation and training dates (recorded cutoff 2019-12-31). Serving refuses origins before training cutoff. These calendar/source marks do not establish historic provider publication, acquisition or input availability.

National scenarios pin source bytes/configuration hash, generation, units, canonical 725-ID registry, unique monthly keys, observation flags and matching groundwater aliases. They take only the requested district's observed/non-imputed/nonnegative history **strictly before the scenario month, even on month end**; they cannot borrow zones. The existing `monthly_projection.fit_projection` calculates an in-memory robust, recency-weighted regularized trend, optional annual sine/cosine cycle, recent level offset and 36-month trend damping. It requires 24 observations spanning 36 months, prefers the last 120 months only if that window has enough observations, and otherwise can use full history. Thus a short monthly curve can depend on very old, sparsely seasonal evidence. No parameters/checkpoints are saved; method/source/config/history hashes identify the calculation. This serving calculation is a transient statistical **fit**, even though it never retrains active ML. It was not executed by this worker.

The separate next-six endpoint estimates the present groundwater base from that seasonal method and uses a verified shared climate XGB model for six delta horizons. Its inputs include assumed target weather, not future target groundwater. Historical fitting uses realized weather as conditional covariates; serving and assumed-weather evaluation use only cutoff-eligible historical same-calendar-month averages, minimum three and maximum ten usable years per field. Weather metadata admits that histories may contain bounded causal fills where field-specific flags are absent. Current depth and future weather are assumptions; they do not become observations, live weather forecasts or twelve-month ML support.

The score remains a project-defined 0–100 uncalibrated index with initial weights LR .20 / XGB .45 / drought frequency .20 / fuzzy .15, normalized over available components. Components use observed history; XGB risk maps a .6 current/.4 predicted-depth mixture, LR measures elapsed-calendar trend, drought frequency is recent exceedance of the early-history depth .8 quantile, and fuzzy combines rainfall deficit with year-on-year depletion. ANN/MLP is not an active ensemble component or route dependency: its classifier learns fuzzy-generated labels, so its recorded classification agreement is FIS imitation, not independent observed crisis accuracy. New twelve-month views did not recalibrate this score, its tiers or extraction sensitivity. Sources: `models/ensemble.py:106`, `:172`, `models/ann_classifier.py:64`, `api/routes/scores.py:28`, current README and UI caveats.
