🎯 XGBoost Walk-Forward Validation

True expanding-window validation to prevent data leakage

How It Works

  • Window 1: Train on 2002–2019 → Predict 2020
  • Window 2: Train on 2002–2020 → Predict 2021
  • Window 3: Train on 2002–2021 → Predict 2022
  • Fresh XGBoost model retrained per window
  • Metrics: RMSE, R², NSE per window

Why Walk-Forward?

Standard k-fold leaks future data into the past. Walk-forward respects temporal ordering — the same way models will be used in production.

for year in [2020, 2021, 2022]: test_window = val_df[val_df["year"] == year] # Train model on EXPANDING window model = xgb.XGBRegressor( n_estimators=500, max_depth=6, learning_rate=0.05 ) model.fit(X_train, y_train) # Predict & evaluate y_pred = model.predict(X_test) rmse = sqrt(mean_squared_error(...)) r2 = r2_score(...) nse = nash_sutcliffe_efficiency(...) # Expand training window current_train = concat([ current_train, test_window ])

⚡ Ensemble Crisis Score

Weighted combination of three components → single 0–100 score

Linear Regression Trend

−8.3%

Long-term directional trend in GWL. Negative weight = improving trend reduces score (as expected).

XGBoost Risk

95.8%

Absolute current depth (MinMax-scaled). Dominant component — deeper water table = higher risk.

Drought Frequency

12.4%

% of months above 80th percentile GWL depth (historically). Captures chronic stress.

District ID Resolver

Bridges numeric CGWB IDs ↔ composite GeoJSON IDs (e.g., 446 ↔ GJ-Gandhinagar). Dashboard and API communicate seamlessly.

Data Readiness Fallback

If a district has <60% valid data months → system falls back to agro-climatic zone aggregation instead of per-district prediction.
