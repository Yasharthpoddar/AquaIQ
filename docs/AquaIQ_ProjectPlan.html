Replanned 10 Sep 2026: LSTM and SHAP are dropped from scope — the advanced layer is now XGBoost only, and the Crisis Score ensemble is Linear Regression trend + XGBoost risk + historical drought frequency. The database has also moved from SQLite to PostgreSQL. Weeks 7–8 below fold in the preprocessing pipeline, Fuzzy Logic, Linear Regression, Perceptron ANN, and the Flask/React skeletons, since those hadn't landed in the repo as of this replan.

SRS, IEEE proposal, and SPIT title page are already complete and submitted to the guide. Nothing below is a writing task for those — every item is real build work: data, models, API, dashboard, testing, deployment. The only documents still ahead are the ESE report and poster (both required deliverables for 02 Nov).

Every workstream — data pipeline, core ML, advanced ML (XGBoost), the Flask API, the React dashboard, and testing — rotates across all three people through the 14 weeks, so nobody is boxed into one lane. Presentation duty at each evaluation is also split three ways and rotates who covers which section, so everyone presents at every phase.

Exactly where every number comes from — no orphan features
3 data sources, all downloaded Week 1 — nothing later depends on anything not sourced up front
  CGWB (india-wris.nrsc.gov.in) → district GWL readings, monthly, 2002–2024
  IMD (imdpune.gov.in) → district rainfall, monthly, 2002–2024 + 30-yr climatological normal
  ERA5 (cds.climate.copernicus.eu) → temperature + evapotranspiration, monthly

10 features engineered — every one traceable to a source above, zero external dependencies
  1. GWL_current, 2. GWL_lag_3mo, 3. GWL_lag_6mo — from CGWB
  4. rainfall_current, 5. rainfall_3mo_avg, 6. monsoon_deficit_pct — from IMD
  7. temperature, 8. evapotranspiration — from ERA5
  9. water_balance_proxy = rainfall − ET — derived, no new source
  10. crop_season_flag — calendar rule (Kharif/Rabi/Zaid), no new source

Dropped from the original scope: GRACE-FO / GLDAS satellite data, NDVI, irrigation_fraction, population_density — none of these ever had a download task, so nobody would have been able to build them anyway. CGWB gives direct well-level ground truth at 15,000+ points, stronger evidence than a satellite proxy where CGWB has coverage — coverage isn't uniform across all 640+ districts though, so thin-data districts fall back to a zone-level aggregate (same agro_climatic_zone) rather than reintroducing GRACE, whose own ~300km resolution wouldn't give real district-level signal there either.
